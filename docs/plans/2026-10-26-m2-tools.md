# M2 Tools, Permission Gate and Undo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The real tool set (read, write, edit, grep, glob, bash), a permission gate with approvals in front of every call, per-turn file checkpoints with undo, and per-run config provenance. This milestone ends Stage 1.

**Architecture:** Tools live in a new `harness.tools` package and depend only on the M1 tool contract and the `Environment` protocol. The gate is a pure function in `harness.agent.gate`. Approval and checkpoint I/O sit behind protocols (`Approver`, `CheckpointStore`), so the loop stays free of filesystem and terminal access. Session-scoped state (the bash working directory, "always allow" rules, which checkpoints were undone) is a projection of the log, never memory-only, so it survives resume.

**Tech Stack:** Same as M1. No new runtime dependencies.

**Spec:** `docs/specs/2026-10-22-flagship1-design.md`, sections 4.4, 4.5, 4.6, 9, 12, 13 row M2, 14 item 9. M1 known gap "run provenance" (`docs/walkthroughs/m1.md`).

**Style of this plan:** this plan gives architecture calls, exact interfaces, invariants and behavioral tests. It contains no implementation code. Implementers write the tests and the code. Every listed test is required. Exact strings marked binding are binding.

## Architecture calls (recorded in Task 7; the starred ones are M2 gate decisions)

1. **Tools are a separate package.** `harness.agent` stays generic and knows only the `Tool` contract. `harness.tools` is one tool set among possible others (MCP tools later register the same way).
2. **Paths.** Tools resolve a relative path against the tracked working directory (`ctx.cwd`). Absolute paths are used as given. A path is inside the workspace if, after `posixpath.normpath(posixpath.join(cwd, path))`, it is relative and does not start with `..`. Absolute paths count as outside. Symlink escapes are not detected (an OS sandbox is M10's concern), and the docs say so.
3. **\*Edit format.** Exact string replacement (`old_string` to `new_string`, optional `replace_all`), with distinct errors for zero matches and multiple matches. The option not taken is a patch format (Codex `apply_patch`). Revisit if failed-edit rates at M6 are high.
4. **\*grep and glob placement.** They are tools built on `env.exec`, preferring `rg` and falling back to `grep`/`find` when `rg` is absent. The `Environment` protocol stays small (exec, read, write, plus one remove method), so a Harbor container or a Flagship 2 sandbox has less to implement.
5. **Bash working directory is logged state.** Each bash call runs in a fresh process (M0 0006). The tool reports the directory the command ended in, the loop records it on `tool_call_finished.cwd`, and the current cwd is a projection: the last recorded cwd in the log, or `AgentConfig.cwd`. Environment variable changes do not persist, and the tool description says so.
6. **Bash side effect class.** `bash` is always `mutating`, so its calls never run concurrently. The gate can still auto-allow known-safe commands by policy.
7. **The gate is a pure function** of the call, the tool, the mode, the policy and the session's allow rules. It returns allow, deny or ask, plus the rule that decided. Only "ask" reaches the `Approver`.
8. **Modes.**
   - `ask`: read-only calls are allowed and everything else asks.
   - `auto-edit`: read-only calls and file edits inside the workspace are allowed; bash and outside-workspace paths ask.
   - `yolo`: everything is allowed.
   - In every mode, a matching deny rule wins.
9. **Bash commands are judged per subcommand.** The command is split on `;`, `&&`, `||`, `|`, `&` and newlines (quote-aware).
   - Deny if any subcommand matches a deny rule.
   - Allow by rule only if every subcommand matches an allow rule.
   - Command substitution (`$(`, backticks), process substitution and here-documents make the command unanalyzable, which means "ask" outside `yolo`.
10. **"Always allow" is a projection.** An `allow_always` decision is logged on `approval_resolved.rule`, and the session's extra allow rules are rebuilt from the log on every gate check. A resumed session keeps them.
11. **Gate order.** All calls of a response are gated up front, in call order, before any executes. Approval waits honor the cancel token. A denied call gets `ToolResult(status="denied")` and never gets `tool_call_started`.
12. **\*Snapshot method.** Snapshots are file copies, read through the `Environment` and stored host-side by a `CheckpointStore`, content-addressed by sha256. Snapshotting is not an `Environment` primitive, a deliberate change from the spec sketch: it works the same against a local dir, a container or a remote sandbox. The option not taken is a git shadow repo. Bash side effects are not covered, and the docs say so.
13. **Write-ahead order for a gated mutating file call:**
    1. `approval_resolved` (when there was a decision to record)
    2. `checkpoint_created`
    3. `tool_call_started`
    4. the run
    5. `tool_call_finished`
    6. the result
14. **Undo is model-visible.** `undo` restores files and appends a new model-layer event `checkpoint_restored`, which the context builder renders as a user message. The model is not left believing edits exist that were undone. Undo restores files only. Rewinding the conversation stays `fork`.
15. **Run provenance.** Every `run()` appends a new internal event `run_started(config, config_id)` after `session_started` (if any) and before repair. Budgets stay per run (0012). Config drift between runs is now visible in the log.

### Task 1: Contract and schema additions, run provenance, cwd projection

**Files:** modify `core/events.py`, `agent/tools.py`, `agent/context.py`, `agent/loop.py`, `env/base.py`, `env/local.py` and `tests/test_boundaries.py`; update `tests/sample_events.py`; create `tests/test_loop_provenance.py`.

**Interfaces (produces):**
- `RunStarted(config: RunConfig, config_id: str)`, type `"run_started"`, layer internal, with a classmethod `for_config(config)` like `SessionStarted`.
- `CheckpointRestored(checkpoint_ids: tuple[str, ...], paths: tuple[str, ...], turns: tuple[int, ...])`, type `"checkpoint_restored"`, layer **model**.
- Both types are added to `EVENT_TYPES` and the `EventBody` union.
- `ToolCallFinished.cwd: str | None = None`.
- `ToolOutput.cwd: str | None = None`. A tool sets it when it knows the directory the call ended in.
- `Tool.touches: Callable[[A], list[str]] | None = None`: the paths, as given in the arguments, that a mutating file tool will modify.
- `Environment.remove_file(path: str) -> None`: removes a file, and is a no-op if it is missing. Implement it in `LocalEnvironment` via `asyncio.to_thread`.
- The context builder renders `CheckpointRestored` as `text_message("user", ...)` with this exact text (binding): `[undo] Restored <paths joined by ", "> to their state before turn <min(turns)>. File edits made in turns <sorted unique turns joined by ", "> are gone.`
- Loop changes:
  - It appends `RunStarted` at the start of every `run()`, after `session_started` on a new session and before repair.
  - It computes the current cwd as the `cwd` of the last `tool_call_finished` with a non-null `cwd`, or `config.cwd`. That value goes into every `ToolContext`.
  - It copies `output.cwd` into `tool_call_finished.cwd`.

**Behavioral tests:**
- **Round trip.** Both new events round-trip through the store, and `sample_events` covers them, so the existing every-type test fails without them.
- **Provenance.**
  - A new session gives `session_started, run_started, user_message, ...`.
  - A second run with a different `AgentConfig.model` appends a second `run_started` whose `config_id` differs.
  - A resumed run puts `run_started` before `repaired`.
- **cwd projection.**
  - A fake tool returning `ToolOutput(cwd="sub")` makes the next call's `ctx.cwd == "sub"`.
  - A fresh `Agent` on the reopened log also sees `"sub"`, which proves the cwd comes from the log.
  - A tool returning `cwd=None` leaves the cwd unchanged.
- **Undo rendering.** The builder turns `CheckpointRestored(("c1","c2"), ("a.py","b.py"), (3,4))` into exactly `[undo] Restored a.py, b.py to their state before turn 3. File edits made in turns 3, 4 are gone.`
- **`remove_file`** removes a file, and a second call is a no-op.
- **Boundary.** The scan rejects `harness.tools` importing `harness.env.local` or `subprocess`, and `harness.agent` importing `harness.tools`.

**Commit:** `feat: run provenance, cwd as logged state, schema additions for undo`

### Task 2: File and search tools

**Files:** create `tools/__init__.py`, `tools/files.py`, `tools/search.py`, `tests/test_tools_files.py`, `tests/test_tools_search.py`.

**Interfaces (produces):** each tool is a `Tool[...]` with a pydantic args model.
- `read_tool()`: name `read`, `read_only`. Args are `path: str`, `offset: int = 1` (1-based line, `ge=1`) and `limit: int = 2000` (`ge=1`).
  - Output is `cat -n` style: the line number right-aligned to width 6, a tab, then the line.
  - Lines longer than 2000 characters are cut, with ` [... line truncated]` appended.
  - If lines remain after the window, append `[... N more lines. Use offset=<next> to continue.]`.
  - A missing file gives an error `file not found: <path>`.
  - A directory gives an error `is a directory: <path>`.
  - Non-UTF-8 content gives an error `not a text file: <path>`.
  - An empty file returns `[empty file]`.
- `write_tool()`: name `write`, `mutating`, `touches=lambda a: [a.path]`. Args are `path` and `content`. It creates parent dirs and overwrites, and returns `wrote <n> bytes to <path>`.
- `edit_tool()`: name `edit`, `mutating`, `touches=lambda a: [a.path]`. Args are `path`, `old_string`, `new_string` and `replace_all: bool = False`. These error strings are binding:
  - `file not found: <path>`
  - `old_string and new_string are identical`
  - `old_string not found in <path>`. If a whitespace-normalized match exists, append ` (a match exists with different whitespace; copy the exact text from read)`.
  - `old_string matches <n> times in <path>; add surrounding context to make it unique, or set replace_all`
  - Success: `edited <path>: replaced <n> occurrence(s)`.
  - On any error the file is byte-identical to before.
- `grep_tool()`: name `grep`, `read_only`. Args are `pattern`, `path: str = "."`, `glob: str | None = None`, `ignore_case: bool = False` and `max_results: int = 200`.
  - It uses `rg -n --no-heading --color never` when `command -v rg` succeeds, and otherwise `grep -rn`.
  - The output lines are `path:line:text`.
  - No match returns `no matches` with status ok.
  - Output is capped by `ctx.max_output_bytes` through `env.exec`.
- `glob_tool()`: name `glob`, `read_only`. Args are `pattern` (a glob like `src/**/*.py`) and `path: str = "."`.
  - It returns matching file paths sorted, one per line, capped at 500, with a trailing `[... N more]`.
  - It uses `rg --files -g` when available, and `find` otherwise.
- `default_tools() -> list[Tool[Any]]` returns read, write, edit, grep, glob and bash (bash arrives in Task 3, so return the first five until then).
- All shell arguments are passed through `shlex.quote`. A test proves that a pattern containing `'; rm -rf x; '` deletes nothing.

**Behavioral tests:** one or more per bullet above, run against `LocalEnvironment(tmp_path)`.
- The search tools are tested twice, through constructor flags `grep_tool(prefer_rg=False)` and `glob_tool(prefer_rg=False)` (default `True`), which force the fallback. This shows the fallback gives the same file set for a simple pattern.
- Edit gets a byte-identical check after every error case.

**Commit:** `feat(tools): read, write, edit, grep and glob over the Environment`

### Task 3: Bash tool

**Files:** create `tools/bash.py` and `tests/test_tools_bash.py`; update `default_tools()`.

**Interfaces (produces):**
- `bash_tool()`: name `bash`, `mutating`.
- Args are `command: str` and `timeout_s: float | None = None` (capped at `ctx.timeout_s`).
- The description says each call runs in a fresh shell, that `cd` persists between calls but exported variables do not, and that output is capped.
- **Cwd capture.**
  - Run the command through `env.exec` with `cwd=ctx.cwd`, wrapped so a bash `EXIT` trap prints a per-call random sentinel followed by `$PWD` as the last line.
  - The sentinel line is stripped from the content.
  - `ToolOutput.cwd` is set to the reported directory, made relative to the environment root when it is inside it, and left absolute otherwise. The tool has no root path, so the wrapper also prints the absolute starting directory, and the root is that start with `ctx.cwd` removed from its end.
  - If the sentinel is missing (the shell was killed, or a timeout cut the output), `cwd` is `None`.
- **Status.**
  - Exit 0 gives `ok`.
  - A non-zero exit gives `error`, with content ending in a line `[exit code <n>]`.
  - A timeout gives `exit_status="timeout"`.
  - A cancel gives `exit_status="killed"`.
  - `output_bytes` and `truncated` come from `ExecResult`.

**Behavioral tests:**
- `echo hi` gives ok, the content `hi`, and cwd unchanged.
- `mkdir -p a/b && cd a/b` gives cwd `a/b`. Through the `Agent`, the next bash call runs `pwd` inside `a/b`.
- `export X=1` in one call, then `echo $X` in the next, prints an empty line.
- `cd sub && exit 3` gives status error, content ending `[exit code 3]`, and cwd `sub`, because the `EXIT` trap also runs on an explicit `exit`.
- A command that prints the sentinel-like text itself cannot spoof the cwd: the sentinel is random per call.
- A timeout kills a background child (reuse the M0 `/proc` check) and gives `exit_status="timeout"`. Through the `Agent`, that call's result is `unknown` (the M1 rule for mutating timeouts).
- A cancel through the token gives `killed`.

**Commit:** `feat(tools): bash with logged working directory`

### Task 4: Permission gate (pure)

**Files:** create `agent/gate.py` and `tests/test_gate.py`.

**Interfaces (produces):**
- `Mode = Literal["ask", "auto-edit", "yolo"]`.
- `Rule(tool: str, pattern: str)` (frozen). The pattern is an `fnmatch` pattern matched against the call's subject: the bash command for `bash`, the normalized path for file tools, and `*` for tools with no subject.
- `Policy(allow: tuple[Rule, ...] = (), deny: tuple[Rule, ...] = ())` (frozen).
- `GateDecision(action: Literal["allow", "deny", "ask"], rule: str | None, reason: str)` (frozen). `rule` is the rule's display form `tool:pattern` when a rule decided, or `mode:<mode>` when the mode decided.
- `split_command(command: str) -> list[str] | None`: the subcommands, quote-aware, or `None` when the command is unanalyzable (architecture call 9).
- `subject(tool_name: str, arguments: dict[str, Any], cwd: str) -> str`
- `inside_workspace(path: str, cwd: str) -> bool` (architecture call 2).
- `decide(*, tool: Tool[Any], arguments: dict[str, Any], cwd: str, mode: Mode, policy: Policy, session_allow: Sequence[Rule]) -> GateDecision`
- `session_rules(events: Sequence[Event]) -> list[Rule]`: parses every `approval_resolved` with `decision == "allow_always"` and a `rule` of the form `tool:pattern`.

**Decision order (binding):**
1. Deny rules. For bash, any subcommand matching gives deny.
2. `yolo` gives allow.
3. Allow rules plus session rules. For bash, every subcommand must match, and an unanalyzable command never matches an allow rule.
4. Mode defaults:
   - read-only gives allow.
   - In `auto-edit`, a `mutating` file tool whose subject is inside the workspace gives allow.
   - Everything else gives ask.

**Behavioral tests:**
- A table-driven test over modes and tools: read-only, `edit` inside the workspace, `edit` outside it, `bash`, and an `external` fake tool.
- Deny wins in `yolo`.
- `ls && rm -rf /` with allow `bash:ls*` and deny `bash:rm -rf*` gives deny.
- `ls && cat x` with allow `bash:ls*` only gives ask, since not every subcommand is allowed.
- `ls; ls` with allow `bash:ls*` gives allow.
- `echo $(rm -rf x)` with allow `bash:echo*` gives ask in `ask` mode and allow in `yolo`.
- Quoting: `echo 'a && b'` is one subcommand.
- `split_command` returns `None` for backticks, `$(`, `<(` and `<<`.
- `inside_workspace`:
  - `src/a.py` with cwd `.` is inside.
  - `../x` with cwd `.` is outside.
  - `../x` with cwd `sub` is inside.
  - `/etc/passwd` is outside.
- `session_rules` reads only `allow_always` decisions, and ignores malformed rules.

**Commit:** `feat(agent): pure permission gate with per-subcommand bash rules`

### Task 5: Approvals in the loop

**Files:** create `agent/approval.py` and `tests/test_loop_gate.py`; modify `agent/loop.py`.

**Interfaces (produces):**
- `Risk(side_effect: SideEffect, rule: str | None, reason: str)` (frozen).
- `Decision(action: Literal["allow", "deny", "allow_always"], reason: str | None = None, rule: str | None = None)` (frozen). `allow_always` carries the rule to add in `tool:pattern` form.
- The `Approver` protocol: `async decide(call: ToolCall, risk: Risk, cancel: CancelToken) -> Decision`.
- `PolicyOnlyApprover`: denies every ask with reason `no approver available; the policy did not allow this call` (binding). This is the headless default.
- `ScriptedApprover(decisions: Sequence[Decision])`: answers in order and records the calls it saw. It is for tests and the chaos harness.
- `AgentConfig` gains `mode: Mode = "ask"` and `policy: Policy = Policy()`. The `Agent` constructor gains `approver: Approver = PolicyOnlyApprover()`.

**Loop behavior:**
- **Gate pass.** After `_resolve` and before batching, gate every runnable call in call order (architecture call 11), with `session_rules(log)` recomputed per call so an `allow_always` takes effect for later calls in the same response.
  - `allow` by a rule (not by a read-only mode default) appends `ApprovalResolved(decision="allow", rule=...)`. A read-only mode-default allow appends nothing. A mutating mode-default allow in `auto-edit` or `yolo` appends `ApprovalResolved(decision="allow", rule="mode:<mode>")`.
  - `deny` by a rule appends `ApprovalResolved(decision="deny", rule, reason)` and the result `ToolResult(status="denied", content="denied: <reason>")`.
  - `ask` appends `ApprovalRequested(call_id, risk=side_effect, rule)`, awaits `approver.decide`, and then appends `ApprovalResolved` with the approver's decision. A deny gets the denied result.
- **Cancellation during approvals.** A cancel while waiting on the approver ends the wait. Every call that is not yet approved gets the not-executed close-out, and the run ends through the normal interrupt path with phase `tool`. An approver exception is treated as a deny with reason `approver failed: <ExcType>: <message>`.

**Behavioral tests:**
- **Mode `ask` with no approver**: a mutating call is denied with the binding reason, and the log has `approval_requested`, `approval_resolved(deny)`, then the denied result, with no `tool_call_started`. A read-only call in the same response runs.
- **Allow and allow_always.**
  - Scripted `allow`: the call runs, and the order is `approval_requested`, `approval_resolved(allow)`, `tool_call_started`.
  - Scripted `allow_always` with rule `bash:pytest*`: a later `pytest -q` call in the same run asks nothing. So does a fresh `Agent` on the reopened log in a new run, which proves the projection.
- **Deny precedence**: a deny rule denies in `yolo`, with no approver call.
- **`auto-edit`**: `edit` inside the workspace runs without asking and logs `approval_resolved(rule="mode:auto-edit")`. `edit` of `../outside.txt` asks.
- **Cancel during an approval wait**: the approver blocks until the token fires. The outcome is `interrupted`, every call is resolved, and nothing executed.
- **Approver exception**: the call is denied with the `approver failed:` reason, and the run continues.
- **Every log** passes `assert_every_call_resolved`.

**Commit:** `feat(agent): approvals in front of every gated call`

### Task 6: Checkpoints and undo

**Files:** modify `store/base.py` (protocol), `agent/loop.py`; create `store/checkpoints.py`, `agent/undo.py`, `tests/test_checkpoints.py`, `tests/test_undo.py`.

**Interfaces (produces):**
- `SnapshotRef(checkpoint_id: str)` (frozen).
- The `CheckpointStore` protocol:
  - `save(checkpoint_id: str, files: Mapping[str, bytes | None]) -> None`. `None` means the file did not exist.
  - `load(checkpoint_id: str) -> dict[str, bytes | None]`.
- `FileCheckpointStore(root: Path)` keeps content-addressed blobs under `root/blobs/<sha256>` and one manifest per checkpoint under `root/<checkpoint_id>.json` (path to hash or null). Writes are atomic (tmp then rename). The same content is stored once.
- The `Agent` constructor gains `checkpoints: CheckpointStore | None = None`. When it is `None`, nothing is snapshotted (and the docs say undo is unavailable).
- **Snapshot step.** Before `tool_call_started` for any tool with `touches`:
  1. Normalize the touched paths against cwd.
  2. Read each through `env.read_file` (missing becomes `None`).
  3. Call `save`.
  4. Append `CheckpointCreated(checkpoint_id, paths, turn)`, where `turn` is the number of `user_message` events in the log so far. That makes it a stable user-turn index across runs.
  - If the snapshot fails, the call does not run. It gets an error result, `snapshot failed: <ExcType>: <message>`.
- `undo(*, log: SessionLog, env: Environment, checkpoints: CheckpointStore, turns: int = 1) -> CheckpointRestored | None`:
  - Pick the last `turns` distinct turn indices that have `checkpoint_created` events not already covered by an earlier `checkpoint_restored`.
  - For each path, restore the content from the earliest checkpoint of those turns: write the bytes, or `remove_file` for `None`.
  - Append and return one `CheckpointRestored`. Return `None` when there is nothing to undo.
  - Undo never touches the conversation.

**Behavioral tests:**
- **Store.** Round trip, including `None`. Identical content is stored once (count the blobs). Manifests survive a reopen.
- **Ordering.** `edit` through the `Agent` logs `approval_resolved` (in auto-edit), `checkpoint_created`, `tool_call_started`, in that order. The snapshot holds the pre-edit bytes.
- **Undo across turns.**
  - Turn 1 edits `a.py` twice. Turn 2 creates `b.py` with `write`.
  - `undo(turns=1)` removes `b.py` and leaves `a.py` as it was after turn 1.
  - A second `undo` restores `a.py` to its original content.
  - A third returns `None`.
- **Undo is visible.** After undo, the next request's last user message is the binding `[undo]` text.
- **Not covered.** A file changed by `bash` in the same turn is not restored (documents the limit), while a file edited by `edit` is.
- **Failed snapshot.** A `CheckpointStore` whose `save` raises means the edit never runs and the file is unchanged.
- **Resume.** Undo works on a reopened log in a new process-like setup (fresh `Agent`, fresh store object on the same root).

**Commit:** `feat: per-turn file checkpoints and model-visible undo`

### Task 7: M2 records, walkthrough and Stage 1 summary

**Files:** create `docs/decisions/0015-edit-format.md`, `0016-grep-glob-placement.md`, `0017-snapshot-method.md`, `0018-permission-gate.md`, `0019-bash-working-directory.md` and `0020-additive-schema-changes.md`, plus `docs/walkthroughs/m2.md`.
