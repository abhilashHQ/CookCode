# M5 walkthrough and cross-questions

This document describes M5 as the code exists on branch `dev`, on top of M0 to M4. Read it with `docs/decisions/0032` to `0034` open, and 0022 for the revised server-wait rule. Where a sentence names a function or file, it exists.

## 1. Map

- `providers/http.py`: `StreamingHttpProvider`, the transport policy shared by both adapters (attempts, backoff, server waits, the cancel race, the atomic rule), plus `SSEDecoder`, `parse_chunk`, `server_wait`, `StreamFailure`.
- `providers/openai_compat.py`: now a codec on top of `http.py`, with no behavior change.
- `providers/gemini.py`: adapter B. `to_contents`, `build_body`, `GeminiStreamAssembler`, `gemini_failure`, `GeminiProvider`.
- `agent/context.py`: `build_request(..., provider=)` drops unreplayable reasoning. Also `dropped_reasoning` and `items_sha256`.
- `core/events.py`: `ModelRequestStarted.items_sha256` and `.reasoning_dropped` (additive, 0020).
- `cli/app.py`: the `gemini` preset, `make_provider`, `--resume`, `--continue`, and the provider resolution order (`apply_provider`).
- `cli/commands.py`: `resume`, `fork`, `sessions`, `replay`.

## 2. The parts worth reading closely

### `http.py:StreamingHttpProvider.stream`
Same loop as M3, now in one place. A server wait over `max_server_wait_s` (120 s) fails fast. Shorter waits are honored even when they exceed the 30 s backoff cap. A protocol supplies `url`, `headers`, `build_body`, `assembler`, `error_failure` and optionally `is_terminator` (`[DONE]` for Chat Completions; Gemini has none).

### `gemini.py:to_contents`
One pass over the items. Assistant-side items go into `model` contents, results into `functionResponse` parts, and adjacent contents with the same role merge. A replayable `Reasoning` contributes its signatures. Each one is popped onto the part it belongs to: a call by provider id, or the text part for `text`. `flush_text_signature` places a leftover text signature as an empty text part inside the same model content before the role switches. `_sign_current_turn` then finds the latest pure user message (text, no function responses) and gives the first call of every later model step `skip_thought_signature_validator` if it has no signature yet (0033).

### `GeminiStreamAssembler`
Text and thought fragments stream as deltas. Function calls arrive whole. Signatures are collected per part. `finish()` refuses a stream without `finishReason` (retryable), resamples `MALFORMED_*`, and emits `Reasoning` (signatures plus summary), then `Message`, then any `OtherItem`, then the calls.

### `context.py:build_request`
Dropping happens before the reorder step, so the builder decides what the model sees and the log records how much was dropped. Adapters keep their own `replayable_to` check as a backstop.

## 3. The life of a provider switch

A session runs on NIM and stops at its turn budget. `harness resume <id> --provider gemini -p "continue"`:

1. `load_resumed` reads the log. `--provider gemini` is explicit, so the NIM model does not carry over and the Gemini preset model applies.
2. The prologue writes `run_started` (gemini) and, if a call was left dangling, `repaired` plus its result, then the user message.
3. `build_request(provider="gemini")` drops the two NIM `Reasoning` items. `model_request_started` logs `reasoning_dropped=2` and the items hash.
4. `to_contents` merges the prompt into the user content that holds NIM's results. That content is not a turn boundary, so NIM's calls get the skip signature.
5. Gemini answers with its own signed call. The next request carries that real signature back.
6. `harness replay <id>` rebuilds all requests under each run's config and reports every one as a match.

## 4. Acceptance

- **Reasoning round-trips on B:** recorded cassette `test_gemini_signed_round_trip`. The second request carries Gemini's own `thoughtSignature` on its function call, the API answered `end_turn`, and CI replays it byte for byte. Live checks also showed that a missing signature is a 400 and that the skip value is accepted.
- **Resume after interrupt in every state:** `tests/test_resume.py` covers interrupts while streaming, during a tool (with `--continue`) and while idle; a crash with a never-started call, a started read-only call and a started mutating call; and budget exceeded, then resumed with more turns. Every resumed log is valid (one result per call) and replays as all `match`.
- **Live:** the Gemini fixture task finished `done` in 8 requests with replay all `match`. The NIM-to-Gemini switch exposed the turn-boundary bug (fixed with a regression test) and then hit the free daily quota (20 requests).

## 5. Gate decisions (owner, 2026-10-26)

- **Which native protocol (0032):** Gemini, because it is the only one with a free key. Anthropic would take an afternoon on the shared transport once a key exists.
- **Reasoning replay rules (0033):** same provider and model id only. Unreplayable reasoning is dropped in the builder and counted. Gemini signatures go back on their parts, and unsigned calls in the current turn get the skip value.

## Cross-questions

1. **Why extract a shared transport instead of writing adapter B from scratch?** The retry, cancel and atomicity logic is the subtlest code in the repo. With one copy, a fix like the server-wait split lands on both adapters at once. Adapter A moved over with all of its tests and cassettes passing unchanged.

2. **Where does a Gemini signature live in our neutral model?** In the response's `Reasoning` item, keyed by the part it came with. The neutral `ToolCall` stays provider-free, and the signature is replayed only to the same provider and model.

3. **What happens when history from NIM reaches Gemini?** NIM's reasoning is dropped and counted. NIM's calls in the current turn get `skip_thought_signature_validator`. Without that, the measured result is a 400.

4. **Why not replay Gemini's thought summaries?** The requirement is the signature. Summaries are a readable digest, so replaying them costs tokens and gains nothing measurable.

5. **What was the bug the live switch found?** A prompt merged into the user content holding function responses. We treated that content as a turn boundary, and Gemini does not. The fix matches Gemini's boundary rule, and a regression test reproduces the sequence.

6. **Why is a 37 s server wait honored when the backoff cap is 30 s?** They are different limits. Backoff is our guess, and the server's wait is a fact. Gemini's per-minute limit asks for about 40 s routinely. Only waits over 120 s, which mean a daily quota, fail fast.

7. **How do you prove the context builder is pure?** Each request logs a hash of its items, and `harness replay` rebuilds them from the log and compares. Every resume test replays its log.

8. **Why hash only the items?** The log stores the system prompt only as a hash and the tools only as names, and both are pinned by the run config. Hashing the full request would make replay impossible without logging the prompt text.

9. **What does fork have to do with crash recovery?** A fork can cut between a call and its result. The new session's first run repairs it exactly like a crash, so one mechanism covers both.

10. **On resume, which model runs?** A flag, else the session's last config, else env, else the preset. A model id carries over only with its provider.

11. **What does `--continue` do that a new prompt does not?** It runs `Agent.run(None)`: repair, then the next step, with no new user message. That finishes an interrupted turn without changing the conversation.

12. **What did the free Gemini tier teach you?** 5 requests a minute and 20 a day, an apparently shared or aliased quota across model ids, and 503 overload on the newest models. Good enough for adapter coverage and cassettes, not for benchmark runs.

## Known gaps in M5

- The fixed turn-boundary rule has not been exercised against the live API, because the daily quota ran out first. It rests on the regression test and the measured acceptance of the skip value.
- Spec decision 10's interactive "ask the user about unknown outcomes" is still not built. Repair hands `unknown` results to the model with an inspect-first instruction in every mode.
- Replay checks the builder, not the adapter. Cassettes cover the adapter.
- Gemini `CONTINUATION` finish reasons are treated as errors.
