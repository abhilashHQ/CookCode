# M0 walkthrough and cross-questions

This document describes M0 as the code exists on branch `m0-foundation`. Read it with the decision records in `docs/decisions/` open. Where a sentence names a function or file, it exists.

## 1. Map and dependency rule

The package is `harness` (a placeholder name until the codename gate). Five areas:

- `core/` holds the data model and pure helpers: ids, cancel token, usage, items, events. No I/O.
- `redact.py` holds `Redactor`. It imports nothing from `harness`.
- `store/` holds the session log protocols and the JSONL implementation.
- `providers/` holds the streaming provider contract and a scripted `FakeProvider`.
- `env/` holds the `Environment` contract and `LocalEnvironment`.

The rule: `core` imports only from `cookcode.core`, never imports `subprocess`, `socket`, `http`, `urllib`, `sys`, `httpx` or `requests`, and never calls `print`, `input` or `open` or touches `environ`. `tests/test_boundaries.py` enforces it by parsing every file under `src/cookcode/core/` with `ast` and checking imports, bare call names and attribute names. It is a static check on direct imports. It does not follow transitive imports, and it catches `os.environ` but not `from os import environ`. `store`, `providers` and `env` each import only from `core` (and `store` also from `redact`). Nothing enforces that between those packages; it holds by convention. All serializable types are frozen pydantic models.

Runtime dependency: `pydantic>=2.9,<3`. Python 3.12 or newer. Linux only, because of `fcntl.flock` and `os.killpg`.

## 2. File by file

### `core/ids.py`
`new_id()` returns a random UUID4 as 32 hex characters. `utc_now()` returns a timezone-aware UTC datetime. Invariant: timestamps are always aware, so they round-trip through JSON with a UTC marker.

### `core/cancel.py`
`CancelToken` wraps an `asyncio.Event`. Public: `cancelled`, `reason`, `cancel(reason="user")`, `async wait()`. Invariant: the first `cancel` call wins and later calls do not change the reason. It is not thread-safe, so call it on the loop's thread.

### `core/usage.py`
`Usage` has `input`, `cache_read`, `cache_write`, `output`, `reasoning`, supports `+`, and exposes `total_input` (input plus both cache counters). `StopReason` is the literal set `end_turn`, `tool_use`, `max_tokens`, `refusal`, `aborted`, `error`. Invariant: `Usage` is frozen; addition returns a new value.

### `core/_union.py`
`tag_or_fallback(known, fallback)` returns a pydantic discriminator function. It reads `type` from a dict or an object and returns it if it is in `known`, otherwise returns the fallback tag. Invariant: an unrecognized `type` never raises at the discriminator; it routes to the catch-all variant. A recognized `type` with a changed shape still fails validation.

### `core/items.py`
Public: `TextPart`, `Message`, `Reasoning`, `ToolCall`, `ToolResult`, `OtherItem`, `UnknownItem`, `Item`, `ITEM_TYPES`, `ITEM_ADAPTER`, `text_message`.

- `Message` has a `role` and a tuple of `TextPart`; `.text` joins the parts.
- `Reasoning` stores `provider`, `model_family`, an opaque `payload` and an optional `summary_text`. `replayable_to(provider, model_family)` is true only when both match exactly.
- `ToolCall` has our `id`, `provider_call_id`, optional `provider_item_id`, `name` and `arguments`.
- `ToolResult` has `call_id` (our id), a `status` (`ok`, `error`, `interrupted`, `denied`, `unknown`) and `content`.
- `OtherItem` keeps a provider item we do not model. `UnknownItem` (with `extra="allow"`) catches any unknown `type` from a newer schema.

Invariants: every item round-trips through JSON to an equal value of the same class; unknown item types are preserved, not rejected. Nothing checks that a `ToolResult.call_id` matches an existing `ToolCall`.

### `core/events.py`
Public: `Event`, `make_event`, `to_json_line`, `from_json_line`, `SCHEMA_VERSION` (1), `RunConfig`, `Limits`, `compute_config_id`, 17 event body classes, `OtherEvent`, `EVENT_TYPES`, `EventBody`.

- The envelope has `seq` (non-negative), `id`, `ts`, `schema_version`, `layer`, `body`.
- Each body class carries `LAYER` (`"model"` for `UserMessage`, `SteerMessage`, `ItemEvent`; `"internal"` for the rest). `make_event` sets the envelope layer from `type(body).LAYER`. A model validator rejects an envelope whose layer disagrees with a known body class. `OtherEvent` is exempt.
- `EventBody` is a discriminated union using `tag_or_fallback`, with `OtherEvent` as the fallback.
- `SessionStarted.for_config` computes `config_id`, the first 16 hex characters of the SHA-256 of the canonical JSON of the `RunConfig`.
- Tool lifecycle events (`ToolCallStarted`, `ToolCallFinished`), approval events, `Interrupted`, `Repaired`, `BudgetExceeded`, `CompactionApplied` and `CheckpointCreated` exist as types in M0; no code in M0 emits them.

Invariants: `from_json_line(to_json_line(e)) == e` for every event type (`tests/test_events.py` covers all types via `tests/sample_events.py`); a JSON line contains no raw newline; the layer always matches the body type for known types.

### `redact.py`
`Redactor(secret_values=(), min_secret_len=8)`, `Redactor.from_env(names, environ)`, `redact_text`, `redact`. Exact secret values replace first (longest first) with `[REDACTED:secret_value]`, then nine regex patterns replace with `[REDACTED:<kind>]`. `redact` walks dicts and lists and rewrites string values and dict keys. The `sk-` patterns are anchored so they never match inside an identifier, and lone surrogates are escaped first. Invariant: redaction is idempotent, and values under 8 characters are never treated as secrets.

### `store/base.py`
Protocols `SessionLog` (`session_id`, `next_seq`, `append`, `read`, `close`) and `SessionStore` (`open`, `read`, `fork`, `list_sessions`), plus `SessionLockedError`, `SessionNotFoundError` and `SessionCorruptError`. These are the seam Flagship 2 can implement differently.

### `store/jsonl.py`
`JsonlSessionStore(root, redactor=None)` and `JsonlSessionLog`. Files are `<id>.jsonl` with a sibling `<id>.lock`.

Invariants of `JsonlSessionLog`:
- At most one open log per session. `__init__` takes `flock(LOCK_EX | LOCK_NB)` on the lock file, so a second open raises `SessionLockedError`. `close` releases the lock and closes both descriptors, and releases the lock even if closing the log descriptor fails. If anything after `flock` fails during open, the lock is released before the error propagates.
- `seq` is strictly increasing with no gaps. The next value is the last stored `seq` plus one, read at open time, and `append` increments it after the write.
- Redaction happens before the write. `append` dumps the event, redacts, validates back into an `Event`, then serializes. The returned event is the redacted one.
- A torn final line is removed on open (`_truncate_torn_tail`) and ignored on read (`_read_events`).
- `tool_call_started`, or any append with `durable=True`, is followed by `os.fsync`. Everything else is written to the page cache only.
- A failed write or fsync truncates back to the last good offset, so the event leaves no bytes and its `seq` is reused by the next append. If the truncate fails too, the log refuses appends until reopened.
- A complete line that does not parse raises `SessionCorruptError` naming the line.
- Appending after `close` raises `ValueError`.

Invariants of `JsonlSessionStore`:
- Every session id is checked against `[A-Za-z0-9][A-Za-z0-9_-]{0,127}` with `fullmatch` in `_path` before it becomes a file name. Ids like `../escape`, `a/b`, `.hidden`, the empty string or anything over 128 characters raise `ValueError`. This blocks path traversal. It applies to `open`, `read` and both ids in `fork`.
- `open(create=False)` on a missing session raises `SessionNotFoundError`.
- `open(create=True)` fsyncs the directory after creating the file.
- `fork(session_id, at_seq, new_session_id)` copies the raw bytes of lines up to and including `at_seq`, so fields from newer schemas survive. It raises `ValueError` if `at_seq` is not an existing seq. It writes a uniquely named tmp file, fsyncs it, publishes with `os.link(tmp, target)` (atomic, fails with `FileExistsError` if the target exists), fsyncs the directory, and unlinks the tmp name in `finally`. A reader never sees a partial fork and an existing session is never overwritten.
- `list_sessions` returns sorted stems of `*.jsonl`, which ignores tmp files.

### `providers/base.py`
`ModelRequest` (model, system, tools, items, max output tokens), `ModelCaps`, `ToolSchema`, stream events `ItemStarted`, `ItemDelta`, `ItemDone`, `UsageReport`, `StreamEnd`, and the `Provider` protocol (`name`, `capabilities(model)`, `stream(request, cancel)`). Invariant: a stream ends with a `StreamEnd` carrying a `stop_reason`; a failure is reported as `stop_reason="error"` with a message.

### `providers/fake.py`
`FakeProvider(script, chunk_size=8, event_delay_s=0.0, caps=None)`, `FakeTurn`, `say()`, `call()`, `FakeScriptExhausted`. It replays scripted turns in order, streams message text as deltas, records every request in `.requests`, and raises `FakeScriptExhausted` when the script runs out. The default stop reason is `tool_use` if the turn has a tool call, otherwise `end_turn`. A `fail_with` turn ends in `error`. Invariants: when the token is cancelled it checks before each item, between deltas, and before each `ItemDone`, then yields `StreamEnd("aborted")`. Items already completed stay; the item in flight is dropped.

### `env/base.py`
`ExecResult` (exit code or `None`, output, byte count, duration, `timed_out`, `cancelled`, `truncated`) and the `Environment` protocol (`exec`, `read_file`, `write_file`).

### `env/local.py`
`LocalEnvironment(root)` and `_CappedBuffer`.
- `_CappedBuffer` keeps the first `max//2` bytes and the remaining `max - max//2` bytes from the end, counts every byte seen, and renders a marker `[... N bytes truncated ...]` between them. Invariants: untruncated output decodes in one pass and is returned verbatim, a truncated render never contains a split character at the cut, and memory is bounded by exactly `max_output_bytes`.
- `exec` invariants: a pre-cancelled token returns without spawning; the process group is always killed in `finally`; `exit_code` is `None` for timeout or cancel; `output_bytes` counts all bytes produced, not just kept.
- `read_file` and `write_file` run in `asyncio.to_thread`. `write_file` resolves symlinks first, so it writes through a link and keeps it. It creates a short hidden tmp file in the real target's directory with mode `0o666` minus the umask, fsyncs it, copies the existing file mode if there is one, `os.replace`s it into place and fsyncs the directory. A reader sees the old or new file entirely, and a failed write removes its tmp file.
- Relative paths resolve against the root; absolute paths are used as given. There is no sandboxing of paths.

## 3. The life of one event

Take `log.append(UserMessage(text="hi"))` on an open `JsonlSessionLog`.

1. `make_event(self._next_seq, body)` builds an `Event`: the `seq`, a fresh `new_id()`, `utc_now()`, `schema_version=1`, and `layer` taken from `UserMessage.LAYER` (`"model"`). The validator confirms the layer matches.
2. `event.model_dump(mode="json")` turns it into plain dicts, lists and strings.
3. `Redactor.redact` walks that structure and rewrites any string that contains a known secret value or pattern.
4. `Event.model_validate` rebuilds a typed `Event` from the redacted data. This re-runs discrimination and the layer check.
5. `model_dump_json()` plus `"\n"` is encoded and written to the `O_APPEND` descriptor in an `os.write` loop. On failure the file is truncated back to the last good offset.
6. If the body type is `tool_call_started` or `durable=True`, `os.fsync` runs. Then `_next_seq` is incremented and the redacted `Event` is returned.
7. Reading: `_read_events` opens the file in binary mode and iterates lines. It stops at the first line without a trailing newline, then decodes each complete line and calls `from_json_line`, which is `Event.model_validate_json`. A line that fails becomes `SessionCorruptError` with its line number.
8. Result: an `Event` equal to the one `append` returned (`tests/test_store.py` asserts `store.read(...) == written`). It equals the original only when redaction changed nothing.

## 4. The life of one exec call

Take `await env.exec("sleep 30 & make test", cwd=".", timeout_s=60, max_output_bytes=20000, cancel=token)`.

1. If the token is already cancelled, return a cancelled `ExecResult` immediately. Nothing is spawned.
2. Create `os.pipe()`. Wrap the read end with `os.fdopen`.
3. Spawn, as a shielded task, `bash -c cmd` with `cwd` resolved against the root, stdin on `/dev/null`, stdout on the pipe's write end, stderr merged into stdout, and `start_new_session=True` so the child leads its own process group. The parent closes the write end right after the spawn, so end-of-file arrives once every process holding it has exited.
4. Inside the `try` whose `finally` is step 6, attach the read end to an `asyncio.StreamReader` with `connect_read_pipe`. Start three tasks: the pump (reads 64 KiB chunks into `_CappedBuffer`), `proc.wait()`, and `cancel.wait()`.
5. Race: `asyncio.wait` on the wait task and the cancel task with `timeout=timeout_s`, returning at the first completion.
6. `finally`: `os.killpg(pid, SIGKILL)` on the group (errors for an already-empty group are suppressed), cancel the cancel-waiter, `await` the wait task to reap the child, wait up to five seconds for the pump to hit end-of-file (then cancel it), and close the transport. This runs on every path, including task cancellation.
7. Build the result. `timed_out` means neither task finished. `cancelled` means the cancel task finished and the wait task did not. `exit_code` is `None` in both cases and `proc.returncode` otherwise. Output is `buffer.render()`, with `truncated` and the true byte count.

Why the own pipe: on Python 3.12, `proc.wait()` for a process created with `PIPE` does not resolve until every holder of the pipe closes it. A backgrounded child would hold it until the timeout. With our own pipe the process object has none, so `wait()` returns when bash exits, and the group kill in step 6 then closes the remaining holders so the pump sees end-of-file.

## Cross-questions

**1. Why event sourcing instead of a plain message list?**
A message list is one view of what happened and it dies with the process. The log records every request, tool call, interrupt and error in order, so context, resume, replay, exports and Flagship 2 checkpoints are projections computed from it. A projection bug gets fixed by recomputing, and nothing is lost. Decision 0001 has the options.

**2. Why JSONL and not SQLite?**
One file per session, append-only, readable with `grep` and `jq`, one writer enforced by `flock`, no migrations. Forking is a prefix copy and torn-write repair is truncating a partial last line. SQLite gives queries across sessions, which M0 does not need. If that becomes hot, I build an index from the logs and keep the logs as the source of truth.

**3. What happens if the process dies halfway through writing a line?**
The line lacks its trailing newline. `_read_events` stops at the first such line, so readers ignore it. When the session is opened for writing, `_truncate_torn_tail` cuts the file back to the last newline before the next `seq` is computed. A complete line that is corrupt is a different case: it raises `SessionCorruptError` with the line number and is not skipped. If a write fails partway instead of the process dying, `append` truncates back to the last good offset, so the partial line never stays behind.

**4. Why fsync only `tool_call_started`, and what can you lose?**
That event is the write-ahead record of intent, and it must be on disk before the tool runs. The fsync syncs the whole file, so every earlier event becomes durable too. Other events are written to the OS but not synced. A process crash loses nothing that was written. A power failure can lose the events after the last fsync, which the design assumes is a suffix of the file. Cost is about one fsync per tool call. `durable=True` forces a sync for any other event.

**5. How do you change the event schema without breaking old sessions?**
Within a `SCHEMA_VERSION`, changes are additive: new optional fields, new event types. Old code reads new event types as `OtherEvent` through `tag_or_fallback`, with unknown fields preserved by `extra="allow"`. That only covers new tags: a new enum value inside a known type fails validation, and extra fields on a known type are dropped in memory (`fork` copies raw bytes, so they survive on disk). A breaking change bumps `SCHEMA_VERSION` and needs a migration applied at read time. That migration does not exist yet: M0 writes the version on every event and nothing reads it back.

**6. Why items rather than messages?**
OpenAI Responses and Codex make reasoning and tool calls top-level items, and Anthropic content blocks map onto items one for one. Messages would force reasoning and calls to live inside another structure. Items keep each provider's output as a flat sequence of typed records with an `OtherItem` escape hatch for what we do not model.

**7. Why is reasoning stored opaque, and what happens when you switch models?**
Reasoning payloads carry provider signatures or encrypted content that only the issuing provider and model family can accept back. So `Reasoning.payload` is stored verbatim, and `replayable_to(provider, model_family)` allows replay only on an exact match. After a model switch, reasoning from the old family should be left out of the request while text and tool history carry over. M0 provides the predicate. The projection that applies it arrives with the loop.

**8. Why redact at write time and not at export? What do you lose?**
Every export, trace and Flagship 2 copy derives from the log, so a secret on disk is a secret everywhere, and export-time redaction depends on every consumer remembering. Write-time redaction removes it at the source. What I lose: it is irreversible, a missed pattern is already on disk, a false positive destroys the original text, and replaying a redacted tool result shows the model placeholder text. The explicit secret values from named environment variables cover secrets no pattern can recognize.

**9. Why a fresh bash process per call instead of a persistent shell?**
Shell state such as `cd` and `export` would live outside the log and vanish on resume, so a replayed session could behave differently from the original. A fresh process per call is stateless, simple to time out and kill, and each call takes an explicit `cwd`. The working directory becomes logged agent state in M1/M2.

**10. Why kill the process group even after the command exits normally?**
A command like `sleep 30 &` returns while its child keeps running. The child shares the group created by `start_new_session=True`, so `os.killpg` in the `finally` block removes it. Without that, background processes would outlive the call and escape later cancellation. If the group is already empty the kill raises `ProcessLookupError`, which is suppressed. `test_background_children_do_not_outlive_the_command` covers it. A process that calls `setsid` leaves the group and escapes.

**11. Why keep the head and tail of long output instead of just the tail?**
Command output puts context at the start (what ran, what was configured) and failures at the end. Keeping only the tail loses the start. `_CappedBuffer` keeps half the budget from each end, never splitting a UTF-8 character at the cut, and inserts a marker with the number of dropped bytes, so the model knows output was cut and how much. Memory stays bounded either way.

**12. How does cancellation reach a running subprocess?**
The `CancelToken` is passed into `exec`. `exec` races `proc.wait()` against `cancel.wait()` (with the timeout). When the token fires, the race ends, the `finally` block kills the process group with SIGKILL, reaps the child, drains output and returns `ExecResult(cancelled=True)` with the partial output. If instead the awaiting task is cancelled, for example by a `TaskGroup` tearing down, the same `finally` still kills the group before `CancelledError` propagates. A cancel that lands during the spawn itself is caught too: the spawn is shielded, so `exec` waits for the pid, kills the group and reaps it, then re-raises. A test cancels after 0 to 14 event-loop yields and checks no process survives.

**13. Why is the store synchronous inside an async program?**
Appends are single short lines written to the page cache, and `fsync` is rare. The loop has to wait for the `tool_call_started` write before it runs the tool anyway, so asynchrony would not buy concurrency there. Open and read are the heavier calls, since both read the whole file. If traces show latency, the first step is `asyncio.to_thread` at the call site. M0 has no loop yet, so this is the intended usage, not something a test exercises.

**14. How do you guarantee a single writer per session, and what changes when Flagship 2 runs many workers?**
`JsonlSessionLog.__init__` takes a non-blocking exclusive `flock` on `<id>.lock`. The lock lives in a separate file so it is independent of the log file's lifecycle: the log can be truncated, rewritten or atomically replaced later (compaction, repair) without the lock moving with the inode. A second open raises `SessionLockedError`, even from the same process, because `flock` is per open file description. The kernel drops the lock when the process dies, so there are no stale locks. Session ids are validated against `[A-Za-z0-9][A-Za-z0-9_-]{0,127}` before they become paths, so an id like `../x` cannot escape the store root (`tests/test_store_fork.py` covers it). The lock is advisory and local: it protects one machine's filesystem and only against code that takes it. Many workers on one host still get one writer per session. Workers on separate hosts or a network filesystem would need a different mechanism, such as a lease held in a shared service. `SessionStore` is the protocol where that swap happens.

## Known gaps in M0

- A corrupt complete line makes the whole session unreadable (`SessionCorruptError`). There is no repair path yet that quarantines the line and lets the agent continue.
- Schema evolution only covers new type tags. A new enum value inside a known type, or a new `layer`, fails validation. Either gate on `schema_version` or fall back per line to `OtherEvent`; decide at the first breaking change.
- Redaction runs over structural fields (`type`, `role`, `layer`). A configured secret value equal to one of them rewrites it.
- Non-finite floats are written as `null` (and `inf` in a typed float field fails to read back). Tuples inside `Any` payloads come back as lists. Payloads should be JSON-native.
- A process that leaves the group (`setsid`, `set -m`, daemons) escapes the kill. Containment needs a cgroup or the sandbox backend.
- The group kill after a normal exit can in principle hit a recycled pgid if the group emptied and the id was reused in between. The window is tiny. A pidfd would close it.
- `schema_version` is written but never checked on read.
- `ToolResult.call_id` is not validated against a `ToolCall`.
- Leftover `.tmp` files from a crash during `fork` are never swept.
